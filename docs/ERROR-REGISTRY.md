# 错误库与防复发规则

本文件记录已经发生过的发布错误。每日准备、上线和验收都必须先读取本库；相同错误再次出现时，除了修正文案，还必须补充自动检查。门禁不通过不得发布。

| 编号 | 已发生错误 | 永久防复发规则 |
| --- | --- | --- |
| ERR-001 | 日期疑问与环境时间冲突时作出未经证实的口头确认 | 同时核对客户端时间上下文、本机、服务器和HTTP Date；仍冲突时请求明确确认，不自行平移证据时间 |
| ERR-002 | 免费节点固定页只加新入口，下方仍保留旧数量、下载和证据 | 同批检查摘要、每日按钮、下载、证据、来源、历史首条和更新日期 |
| ERR-003 | 构建脚本重复运行产生重复卡片或重复section | 整合脚本必须连续运行两次，关键URL、ID和RSS GUID数量不得变化 |
| ERR-004 | 把下载YAML哈希误标为测试配置哈希 | 分别保存测试配置、下载文件和语义连接参数指纹，并验证连接参数等价 |
| ERR-005 | “拟用URL、目标搜索意图、计划发布”等编辑流程文字进入读者页面 | 发布前扫描HTML、站内搜索和RSS，命中泄漏词立即失败 |
| ERR-006 | 首页、固定页、日期页和历史归档的数量或地区口径不一致 | 候选、完成测试、合格、下载、备选、协议和地区统一从一个批次manifest生成 |
| ERR-007 | 把准备、测试或复制完成称为已发布 | 只有生产URL、下载、证据和线上哈希验收通过后才写“已发布” |
| ERR-008 | 把HTTP请求失败率写成丢包率 | 双探针只写请求成功次数/失败率；只有测试工具原生报告packet loss才写丢包率 |
| ERR-009 | 页面不一致时未读线上源HTML就归因于缓存 | 先抓取线上HTML和响应头；源HTML正确而浏览器仍旧时才讨论缓存 |
| ERR-010 | 只验收新日期页，没有验收所有消费面 | 同批检查首页、固定页、历史归档、文章库、搜索、RSS、sitemap和GitHub记录 |
| ERR-011 | 线上热修复完成，但后续预览仍从旧静态副本构建 | 热修复后必须更新生成源或设为新基线，并重新扫描旧日期、旧数量和旧证据链接 |
| ERR-012 | 当天发布的内容误标为次日，提前占用次日日期页 | 发布前核对北京时间和测试完成时间；日期页、下载、证据、RSS、sitemap及仓库统一使用实际发布日期 |
| ERR-013 | 双栈出口因 IPv4 和 IPv6 字符串不同而被误判为地区冲突 | 两端先核对地址组合，再分别由两家独立地理来源核验每个地址；地址缺失或真实地区冲突仍拒绝 |
| ERR-014 | 复用页面模板时带入不相干的 FAQ 结构化数据 | 所有 JSON-LD 问答必须对应可见正文；新页面审计逐项检查并移除旧模板问答 |
| ERR-015 | 旧教程把近期节点概称为海豚第三方筛选 | 稳定教程只引导读者查看各期实际测试方法，不预设后端；改变方法时扫描相关入口 |
| ERR-016 | 上线前复测在代理端口未就绪时误报节点不可连接 | 启动测试进程后先确认本地代理端口可接收连接，再开始实际请求；失败记录区分测试器启动错误与代理请求失败 |
| ERR-017 | 8 个已发布页面漏装前端统计，导致整站访问被低估 | 每次上线后以 sitemap 全量 URL 为清单，检查每个 HTML 页面恰好加载一次统计脚本；报访问数据前先核对覆盖率和统计窗口 |
| ERR-019 | 11 月 6 日六页优化上线时，节点罗盘已更新但站内搜索索引漏掉该入口，首次验收失败 | 发布前以变更页面URL为清单检查搜索索引及实际搜索结果；验收脚本同时断言每个约定搜索入口存在，缺项立即补齐并复验 |

## 每次发布必须输出

- 预期日期与数量；
- 所有消费面的同步结果；
- 受保护页面身份对照；
- 重复ID、旧日期、旧数量和编辑流程词扫描；
- 聚合与单条下载数量；
- 测试配置到下载配置的等价性；
- 线上验收URL数量与问题清单；
- 可恢复备份位置；
- GitHub同步提交。
- 全量页面统计脚本覆盖率及重复加载检查。

发现新错误时按“现象、根因、永久规则、自动检查、状态”五项追加，不得删除历史错误。
